## 4. 최근 해결한 것

같은 실수를 반복하지 않도록 **증상과 원인**을 남긴다. 전부 회귀 테스트를 붙였다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 서울 일정에 대구·청주가 섞임 | `_in_region` 이 `search_events` 에만 걸려 있었다 | 시설 API에도 적용 + 거리 상한 60km |
| `세종문화회관` 이 걸러짐 | "세종"이 지역명 목록에 있었다 | 목록에서 제외, 거리 상한이 대신 받음 |
| 과거 불편 기록이 안 붙음 | 후보는 `external_key`, 아카이브는 uuid — 식별자 공간이 달랐다 | `places.id` 로 통일 + `link_place_ids` |
| 카드 제목과 내용이 다른 장소 | seq로 이름을 다시 조회 → 재편성 후 어긋남 | `Issue.place_name` 에 검사 시점 이름 고정 |
| 이슈 6건이 카드 25장 | `Issue.id` 가 매번 새로 생성 | 카드 id를 `adv-{kind}-{place}` 로 고정 |
| 해결된 이슈의 카드가 안 사라짐 | 검증 결과를 누적 병합 | `replace_list` 리듀서로 교체 |
| 응답이 26초까지 튐 | 도구 타임아웃 12초 > 총예산 15초 | `safe_call(deadline=)` 예산 인지 |
| `/routes`·`/verify` 만 500 | 체크포인터가 단일 연결, 끊기면 영구 실패 | 커넥션 풀 + 체크아웃 검사 |
| 502 하나로 요청 전체가 죽음 | 임베딩 호출이 try 바깥이었다 | 가드 안으로 이동 |
| 리랭크가 조용히 꺼져 있음 | 모델이 404인데 예외를 삼킴 | 살아 있는 모델로 교체 + 실패 로그 |
| 체류시간이 기본값 고정 | `avg_dwell_min` 을 계산만 하고 미사용 | 사용자가 말 안 했을 때 배율 보정 |
| pg18 기동 실패 | 마운트 지점이 바뀜(`/var/lib/postgresql`) | compose·Dockerfile 수정 |
| 도착 안내가 2번째 장소를 가리킴 | `fill_gaps` 가 장소를 늘린 뒤 `notes` 를 다시 안 만듦 | `endpoint_notes()` 한 곳으로 모으고 장소가 바뀌는 모든 지점에서 재계산 |
| 「문화 2 + 디저트 3」이 8곳이 됨 | 앞 숫자만 잡아 `stop_count=2`, 빈틈 채우기는 `MAX_STOPS` 만 봄 | `KIND_GROUPS` + `kind_quota` 로 종류별 배분, 못 채운 몫은 자리를 비워 둠 |
| 지도 실패가 화면 전체를 죽임 | `NaverMap` 의 `useCallback` 이 조기 반환 **아래**에 있어 훅 수가 줄었다 | 훅을 조기 반환 위로 이동 |
| 기획안의 대표 화면(선제적 알림)이 안 뜸 | UR-11·UR-12 를 걷어내며 **생산자만** 사라지고 스키마·카드는 남았다 | `validation.check_friction` 으로 복원(검증 5→6종) · 계약 테스트 이름도 함께 변경 |
| 수정 행동이 세션을 넘기면 사라짐 | `edit_signals` 를 계산해 프로필에만 반영하고 `plan_edits` 에 안 남겼다. 게다가 재집계는 방문 기록만 보므로, 방문이 하나 들어오면 그 반영분까지 지워졌다 | `persist → save_plan_edits()` 로 남기고 `rebuild_profile()` 이 되읽는다 |
| 처음 만든 일정에서 카드로 뺀 장소가 안 배워짐 | 신호를 두 일정의 diff 로만 뽑는데, 비교 대상(`current_itinerary`)은 **수정 요청일 때만** 불러온다 | 확정 카드 선택을 직접 신호로 읽는다(`_decision_signals`) |
| 「서초구」 요청에 판교 장소가 1번 | 지역 판정이 거리 하나뿐이었다. 판교는 25km라 상한 60km를 통과한다 | 시·도를 지오코딩·주소에서 읽어 다르면 제외(`tools/region.py`). 말한 구는 가점으로 앞에 온다 |
| '세종문화회관'이 세종시로 읽힐 뻔함 | 짧은 시·도 이름을 문자열 아무 곳에서나 찾으면 고유명사에 걸린다 | 시·도는 **맨 앞에서만**, 뒤에 경계(공백·쉼표·끝)가 올 때만 읽는다. '경기도 광주시'도 같은 규칙이 지킨다 |
| 분할하다 함수의 마지막 `return` 한 줄이 잘림 | 줄 범위 끝을 1 적게 잡았다. 옮긴 코드는 눈으로 봐선 멀쩡해 보인다 | 옮긴 뒤 **AST 로 최상위 정의를 이름별 대조**한다(소스 문자열이 글자 그대로 같은지). 테스트보다 먼저, 더 정확히 짚는다 |
| 같은 «싫다»가 여러 번 쌓일 뻔함 | 카드 결정은 스레드 상태에 남아 다음 요청에서도 지나간다 | 신호 id 를 결정·일정에서 만들어 저장 쿼리가 중복을 거른다 |
| 프로필 행이 없는 첫 사용자는 못 배움 | `_learn_from_edits` 가 `load_profile() is None` 이면 그냥 돌아갔다 | 재집계로 만들어 저장한다(방금 남긴 `plan_edits` 가 이미 반영돼 있다) |
| 「문화생활 + 디저트 2개」에 일정이 **0곳** | 세 겹이 물려 있었다. ① `.env` 에 `MODEL_*` 이 비어 NIM 기본값이 planner·writer 를 70B 로 잡아 compose 12.3초 + 라우터 8B 가 출발지·시각을 비움 ② 「디저트 2개」가 종류별 몫이 아니라 **전체 총량**으로 잡혀 문화 자리가 사라짐 ③ 몫의 후보가 없으면 `schedule` 이 첫 반복에 `break` 해 아무것도 못 넣음 | ① 권장 배선 적용 ② `stop_count` 는 **말한 종류 전부에 개수가 붙었을 때만** 확정 ③ 몫만큼 자리는 남기되 **편성은 계속** |
| 「문화 및 식사 5개」가 식사 5개로 읽힘 | 개수 앞 창에서 낱말 하나만 집어 `{food:5}` 로 잡았다. 합이 총량과 우연히 같아 오래 가려져 있었다 | 창에 **종류가 둘 이상**이면 총량으로 본다. 창은 앞 개수 표현에서 끊는다 |
| 한글 조합 중 Enter 가 전송으로 오인 | RNW 는 `onSubmitEditing` 앞에서만 `isComposing` 을 보고 `onKeyPress` 는 그보다 먼저 무조건 부른다 | `Composer.onKeyPress` 에서 `isComposing`·`keyCode 229` 를 직접 거른다 |

## 5. 알아 둘 함정

**`.env` 를 고치면 재생성해야 한다.** `restart` 로는 반영되지 않는다.

**시드 데이터는 볼륨에 있다.** 컨테이너를 지워도 `culturemate_pgdata` 가 남아
있으면 안전하다. `docker compose down -v` 나 `docker volume rm` 만 조심하면 된다.

**체크포인트가 오염될 수 있다.** 오래 쓴 스레드는 옛 스키마로 직렬화된 객체를
들고 있어, 스키마를 바꾸면 이상하게 보인다. 앱에서 새 대화를 시작하면 정상이다.
전부 비우려면:

```bat
docker exec culturemate psql -U culturemate -d culturemate -c "TRUNCATE checkpoints, checkpoint_blobs, checkpoint_writes"
```

**모델을 바꾸기 전에 재 볼 것.** `scripts/bench_models.py` 가 있다. 단, 이
스크립트의 기본 라우터 작업은 축소 스키마라 실제보다 훨씬 빠르게 나온다.
